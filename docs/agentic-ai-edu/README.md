# Agentic AI Edu 실습 가이드북

제조·중소기업 실무자를 위한 3일 과정입니다. GitHub의 Streamlit 챗봇으로 브라우저 입력 → 파이썬 처리 → 화면 응답을 확인하고, 같은 작업 흐름을 회사 업무 앱에 적용합니다. 하루 3시간씩 진행합니다.

[수업 교안](https://docs.google.com/presentation/d/1Pq_oT0wPWZFYoaGuRbEJP8-OdBorqypbJWygIqAdxEc/edit)

## 1일차 · 웹앱 실행과 기획

준비물은 Git, Python, 편집기, Claude Code 또는 Codex CLI입니다. 실습에서는 가상 데이터만 사용합니다.

```powershell
git clone https://github.com/bsmkorea1216sj/chatbot.git
cd chatbot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run streamlit_app.py
```

브라우저에서 터미널이 표시한 로컬 주소를 엽니다. 키 입력 안내 화면이 뜨면 로컬 실행에 성공한 것입니다. API를 사용할 수 있는 교육 환경에서는 가상 질문으로 응답을 확인합니다. 원본 코드의 모델 이름은 `gpt-3.5-turbo`이므로 호출 가능 여부는 실습 계정에서 확인합니다. 키가 없거나 호출이 실패하면 에이전트에게 고정 응답 모드를 별도 실습 브랜치에 만들도록 지시하고, 그 결과를 API 호출 성공과 구분해 기록합니다.

[실습에 사용하는 챗봇 코드](https://github.com/bsmkorea1216sj/chatbot/blob/main/streamlit_app.py)

`PLAN.md`에 사용자, 입력, 처리, 화면, 완료 조건을 적습니다. 예를 들어 현장 작업자가 작업일·공정·담당자·작업 내용·수량을 등록하고 반장이 목록에서 일자와 공정으로 검색합니다. 1일차 산출물은 기획서와 로컬 첫 화면, 첫 커밋입니다.

## 2일차 · 구현, 검증, GitHub

챗봇에서 `st.chat_input`은 입력, `st.write_stream`은 응답 표시, `st.session_state`는 같은 세션의 대화 기록을 맡습니다. 업무 앱은 입력을 검증한 뒤 SQLite에 저장하도록 설계합니다. 기준 PPT의 업무 앱은 FastAPI와 Jinja2를 사용하는 별도 실습 프로젝트입니다.

에이전트에게 등록과 목록부터 구현하도록 지시합니다. 그다음 기간 검색을 추가합니다. 규칙 파일에는 작업 범위, 파일 단위 변경, 가상 데이터 사용, 키 관리, 검증 후 커밋의 다섯 가지를 적습니다. 다른 에이전트에게 변경 내용을 검토하게 하고, 제안은 실제 실행 결과를 확인한 뒤 반영합니다.

| 확인 항목 | 기대 결과 |
| --- | --- |
| 공정 A에서 수량 12 등록 | 목록에 한 건 추가 |
| 수량 -1 제출 | 입력 오류 표시, 기존 데이터 유지 |
| 서버 재시작 후 목록 열기 | SQLite에 저장한 기록 유지 |
| 날짜 범위 밖의 기록 검색 | 해당 기록 제외 |
| 키 없이 챗봇 실행 | 키 입력 안내 표시 |

업무 앱 저장소에 실행 절차와 의존성을 기록합니다. 기획, 화면, 저장, 검색·검증, 배포 갱신을 분리해 커밋 5개를 남깁니다. `git diff --cached`로 올릴 파일을 확인하고 API 키와 비밀번호는 Git에 넣지 않습니다.

## 3일차 · 배포와 갱신

1. 오라클 VM에서 강사가 지정한 실습 저장소를 복제하고 가상환경에 의존성을 설치합니다. 로컬에서 쓰던 실행 명령으로 먼저 서버 내부 응답을 확인합니다.
2. 기준 업무 앱은 FastAPI를 실행할 Uvicorn 서비스를 등록합니다. 서비스에 작업 디렉터리, 실행 사용자와 실행 명령을 명시합니다. 접속 포트와 방화벽 규칙은 실습 서버 설정을 따릅니다.
3. 다른 기기에서 접속해 가상 기록을 등록하고 조회합니다. 서버에서 실행 상태와 로그를 확인합니다. 접속이 안 되면 앱 응답 → 수신 포트 → VM 방화벽 → 클라우드 인바운드 규칙 순서로 확인합니다.
4. 로컬에서 화면 문구를 수정해 push합니다. VM에서 `git pull --ff-only`로 반영하고 서비스를 재시작한 뒤 같은 주소에서 변경을 확인합니다.
5. 확장 실습은 GCP Cloud Run입니다. 컨테이너가 플랫폼의 포트를 사용하게 설정하고 외부 주소에서 확인합니다. SQLite 기록의 지속 보존이 필요한 앱은 외부 저장소를 연결하는 과제로 분리합니다.
