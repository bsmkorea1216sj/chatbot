# AI노마드 예약금 자동화 BM v2.0

> 작성일: 2026-11-01
> 전 버전: BSN Korea 소상공인 예약 자동화 마이크로 SaaS 기획서 (2026-11-01)
> 변경 사유: 전 버전의 상품 정의(예약 관리 SaaS)는 무료 대체재 3개(개인 카톡,
> 카카오톡 예약하기, 무료 고객관리 앱)와 정면 경쟁이며, 월 20,000원 가격으로는
> 방문 영업 CAC를 회수하지 못함. 상품을 예약 관리에서 **예약금 수취**로 좁힌다.

## 0. 한 문장

**고단가 예약 업종의 신규 손님 노쇼를 예약금으로 막아주는 단일 기능 서비스.
원장님의 카톡 운영은 그대로 둔다.**

전 버전과의 핵심 차이 두 개:

| | v1 | **v2** |
|---|---|---|
| 상품 | 예약 관리 시스템 | **예약금 수취 + 조건부 룰 + 자동 리마인더** |
| 카톡과의 관계 | 대체 | **보조 — 상담·대화는 계속 카톡** |

## 1. 사업 개요

### 1.1 컨셉

- 원장은 지금처럼 카톡으로 손님과 대화한다. 바꾸지 않는다.
- 시스템이 맡는 것은 셋뿐: **예약금 링크 / 조건부 적용 룰 / 자동 리마인더**
- 전면 교체(rip-and-replace)를 요구하지 않으므로 전환 비용이 거의 없다.
- 진입 경로가 카카오톡 안이므로 **손님의 행동 변화가 0**이다. 별도 앱 설치가 없다.

### 1.2 타겟 — 업종을 좁힌다

| 순위 | 업종 | 근거 |
|---|---|---|
| 1차 | **애견미용** | 단가 6~8만원, 예약 필수, 노쇼 시 대체 손님 즉시 불가 |
| 2차 | **왁싱 · 네일 · 피부관리** | 단가 5~8만원, 반복 방문, 시간 블록 60분+ |
| 3차 | 일반 미용실 | 커트 단가가 낮아 예약금 저항. 고단가 시술만 적용 |
| 제외 | **카페** | 예약 행위 자체가 거의 없음. 상품 가치가 작동하지 않음 |

대상 조건: 1~3인 샵 / 시술 1건 블록 60분 이상 / 네이버·카톡으로 예약 접수 /
**개업 1개월 이상**(네이버페이 결제형 운영 이력 조건).

### 1.3 경쟁 — 유일하게 비어 있는 칸

| 대체재 | 예약 접수 | 예약금 수취 | 조건부 룰 | 세팅 대행 |
|---|---|---|---|---|
| 개인 카톡 + 전화 + 장부 | O | X | X | — |
| 카카오톡 예약하기 | O (**무료**) | 결제 연동 가능 | X | X |
| 무료 고객관리 앱(공비서 등) | O (무료) | X | X | X |
| **AI노마드** | 카톡 그대로 | **O** | **O** | **O** |

차별점은 두 개로 좁힌다: **조건부 예약금 룰**, **업종별 세팅 대행**.

> **플랫폼 리스크 (명시)**
> 카카오가 조건부 예약금을 기본 제공하면 이 사업은 끝난다. 카카오는 이미
> 2026년 59개 상권 1,265명 상인을 교육해 채널 4,000개를 확보했다 — 같은 상권을
> 먼저 돌고 있다. 그래서 가치를 카카오가 복제하기 어려운 축에 둔다:
> ① 좁은 업종 지식 ② 세팅 대행과 신뢰 ③ 유튜브 청중.
> 그리고 **12개월 내 회수 가능한 규모로만** 설계한다. 플랫폼 의존 사업에
> 장기 베팅하지 않는다.

### 1.4 가격

| 항목 | 금액 | 역할 |
|---|---|---|
| 세팅비 | **200,000원** (일회성) | **CAC 즉시 회수** |
| 기본 | **월 49,000원** (VAT 별도) | 예약금 링크·룰·알림톡 300건·캘린더 |
| 상위 | 월 99,000원 | 다지점·디자이너별·재방문 캠페인·리포트 |
| 사용량 | 알림톡 초과 15원/건 | 변동비 전가 (원가 7~10원) |
| 파일럿 | 3곳만 세팅비 면제 + 3개월 무료 | 사례 확보 대가 |

산출 근거:

- 공헌이익 = 49,000 − PG 1,715(3.5%) − 알림톡 1,760 − GCP 300 ≈ **45,000원**
- 방문 영업 CAC 30~60만원 → 세팅비 20만원으로 절반 이상 즉시 회수
- 회수 기간 **약 7~9개월** (v1의 17~35개월 대비)

소상공인은 "월 구독"보다 **"설치비 + 월 유지비"**에 익숙하다 (POS, 간판, 키오스크
모두 그 구조). 세팅비는 가격 저항이 아니라 **가격 신뢰** 장치다.

### 1.5 수익 모델

세팅비(CAC 회수) + 구독(마진) + 알림톡 사용량(변동비 전가 + 약 2배 마크업).

**예약금 결제 수수료는 받지 않는다.** 가게 가맹점 직수취 구조이므로 대금이
AI노마드를 거치지 않는다 (2.1 참조). 수수료를 받으려면 규제 등록이 필요하다.

## 2. 결제 구조 — 규제 안전 설계가 최우선

### 2.1 예약금: 가게 명의 직수취, AI노마드 미경유 ★

시스템은 **주문 정보만 생성**하고, 결제는 **가게 본인 가맹점 명의로 직접 수취**된다.
AI노마드 계좌를 절대 거치지 않는다.

- **이유**: 타인(가게)의 대금을 수취·정산하면 전자금융거래법상
  전자지급결제대행(PG) 또는 결제대금예치업에 해당해 금융위 등록 대상이 된다.
  등록 없이 운영하면 사업 자체가 불법이다.
- **구현**: 가게가 자신의 네이버페이·카카오페이·나이스 가맹 정보를 입력 →
  시스템은 그 가맹 정보로 결제창만 호출 → 정산은 PG에서 가게로 직접.
- **환불**도 가게 가맹점에서 발생한다. 시스템은 요청 전달과 기록만 담당한다.

**이 구조가 틀리면 상품 전체를 다시 설계해야 한다. 코드 한 줄 전에 확정한다.**

### 2.2 구독료: 나이스페이먼츠 빌링키

v1 판단 유지(가입비 없음, 빌링키 지원 양호). 세팅비는 1회 승인, 구독은 월 자동결제.
거래량이 늘면 토스로 이전 — API 연동이라 교체 비용이 낮다.

### 2.3 계약 전 확인 필수 (미확정)

- [ ] 나이스 가입비 실제 조건 (0원 / 33만원 중 무엇인지)
- [ ] 네이버페이 결제형 "1개월 운영 이력"이 **가게 단위**인지 → 신규 개업 샵 제외 여부
- [ ] 예약금 환불 기준: 소비자분쟁해결기준·전자상거래법상 취소 시점별 환불율
- [ ] 표준 약관(예약금·취소·노쇼) 문안

## 3. 인프라

### 3.1 설계 (v1 3.1절 수정)

- **단일 GCP 프로젝트 + Firestore 경로 테넌트 분리** (`/tenants/{shopId}/...`)
  - v1의 "테넌트별 GCP 프로젝트 분리" **폐기**: 프로젝트 수 할당량, 프로젝트별
    API·IAM·배포 반복, 운영 복잡도 폭증. v1의 "비용 0원" 목표와 정면 충돌한다.
- Cloud Run (서버리스), Firebase Auth (원장 로그인), Cloud Tasks (리마인더 스케줄)
- **브라우저에 Firestore 직접 쓰기 권한을 주지 않는다.** 서버 서비스 계정만 쓴다.
- 리전 asia-northeast3

### 3.2 재사용 자산 — 신규 개발을 최소화한다

이 저장소에 이미 있는 것:

| 자산 | 재사용 대상 |
|---|---|
| `services/research-api/` | Firebase 인증, 예약/정산(reserve·settle) 원장, Cloud Tasks 워커, 중복 요청 방지 |
| `scripts/gcp_deploy/` | gcloud 없는 단계별 배포 실행기, 토큰 인증, 기본 도메인 URL 발급 |

→ 인증·원장·작업큐·배포는 그대로 쓰고 **예약 도메인만 신규 개발**한다.

### 3.3 Oracle Cloud 전환 — 폐기

7일 유휴 시 회수, 인기 리전 용량 부족, 사전 공지 없는 무료 티어 축소(2026.06).
예약 서비스를 올릴 인프라가 아니다. 가게 수백 개는 Cloud Run 무료 티어 근처에서
처리된다.

## 4. 기능 요구사항 — 1차 범위를 극단적으로 좁힌다

### 4.1 MVP (이것만. 4주)

1. **예약금 링크 생성** — 시술·금액·만료시간 지정, 카톡에 붙여넣을 URL 하나
2. **조건부 룰 엔진** ★ — 신규 손님만 / 단골 면제 / N원 이상만 / 주말만. **핵심 차별**
3. **자동 리마인더** — 알림톡: 예약 확인, 24시간 전, 노쇼 후 안내
4. **예약 캘린더** (읽기 중심) — 중복 예약 방지, 잔여 슬롯
5. **원장 로그인** (Firebase Auth)
6. **현황 1화면** — 입금·노쇼 건수

### 4.2 2차 (파일럿 통과 후)

단골 자동 판별(방문 2회 이상), 월 리포트, 재방문 캠페인, 디자이너별 슬롯, 다지점

### 4.3 범위 밖 — 의도적 제외

손님용 앱, POS 연동, 매출 관리, 재고, 급여. 전부 다른 제품의 일이고 무료
대체재가 이미 한다. 여기에 손대면 1.3절의 차별점이 흐려진다.

### 4.4 자동화 루틴

리마인더 발송 큐 / 미입금 예약 자동 취소(만료 시) / 구독 갱신 알림 / 주간 리포트

### 4.5 상품 디테일 — 예약금을 전면 적용하지 않는다

전면 적용하면 손님이 옆 가게로 간다. **조건부**가 현실적인 설계다.

> 기본 룰: **신규 손님 + 3만원 이상 시술에만 예약금 1만원. 단골은 면제.**
> "단골은 그냥 오시고, 처음 오는 분만 1만원" — 원장이 설명하기 쉽고 손님도 납득한다.

이 룰 엔진이 제품의 핵심이며, 카카오톡 예약하기는 업종별 조건부 정책을 제공하지
않는다.

## 5. 마케팅 — v1의 순서를 뒤집는다

### 5.1 1순위: 유튜브 (AI노마드)

근거는 v1 7.1절 본인 인용: **"청중 보유 창업자 중앙값 월 $40,000 vs 미보유 $2,000"**.
보유한 유일한 비대칭 자산이다. v1은 이걸 인용해 놓고 유튜브를 3순위에 두었다.

- 1화 소재 = 파일럿 1곳의 **노쇼 before/after 숫자 하나**. 그게 전부다.
- 영상 1편이 1년 이상 유입을 만든다는 것도 v1의 주장이다.

**브랜드 통일**: BSM / BSN Korea / AI노마드챗봇 / AI노마드연구소 → **AI노마드** 하나로.
청중이 최대 자산인데 브랜드 4개로 흩어지면 그 자산이 모이지 않는다.

### 5.2 2순위: 파일럿 3곳 직접 확보

방문 영업을 **"판매 채널"이 아니라 "사례 수집 수단"**으로 재정의한다.
3곳 확보하면 중단한다. v1처럼 방문을 주 채널로 쓰면 CAC가 사업을 깬다.

### 5.3 3순위: 업종 커뮤니티

애견미용·왁싱은 네이버 카페·인스타 중심의 좁고 밀도 높은 커뮤니티가 있다.
소상공인연합회 같은 큰 협회보다 여기가 먼저다.

### 5.4 정부 지원 — 영업 포인트로 사용

스마트상점 기술보급사업(SW형 연 30만원 100% 지원)이 있으면 **세팅비 20만원 +
구독 몇 달이 지원 범위에 들어간다.** 인지율이 43%라면 안내 자체가 차별화다.
단 **사업 공고는 매년 바뀌므로 신청 전 당해 공고를 확인**한다.

## 8. 액션 아이템 — 0원 검증이 1번이다

각 게이트를 통과하기 전에 다음으로 넘어가지 않는다.
**v1의 실패 패턴은 게이트 0~2를 건너뛰고 3으로 가는 것이었다.**

### 게이트 0 — 수요 검증 (3일, 0원, 코드 0줄)

애견미용·왁싱 **20곳 전화/방문**. 질문 두 개만:

1. "지난달 노쇼 몇 건이었습니까?"
2. "신규 손님에게 예약금 1만원 받아주는 기능이 있으면, 월 5만원에 쓰시겠습니까?"

**통과 기준: 10곳 중 3곳이 "노쇼 월 5건 이상" AND "쓰겠다". 미달 시 폐기.**

### 게이트 1 — 효과 검증 (1주, 0원, 코드 0줄)

파일럿 3곳에 **수동** 예약금 링크 운영. 시스템 없이 결제 링크만 만들어 원장이
카톡으로 직접 보낸다. 노쇼율 변화 측정.

**통과 기준: 3곳 중 2곳에서 노쇼 감소. 미달 시 룰 재설계.**

### 게이트 2 — 법무 (코드 전)

- [ ] 예약금 가게 직수취 구조 확정 (2.1)
- [ ] 표준 약관·환불 기준
- [ ] 개인정보 위탁계약서 — 가게가 처리자, AI노마드가 **수탁자**

### 게이트 3 — MVP 개발 (4주)

4.1절 6개 기능만. 범위 확대 금지.

### 게이트 4 — 유튜브 1화

게이트 1의 before/after 숫자로 촬영.

### 게이트 5 — 유료 전환 3곳

세팅비를 실제로 받는다. **여기까지 오면 BM이 성립한다.**
