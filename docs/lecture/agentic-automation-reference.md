# 에이전틱 AI 업무 자동화 — 강의용 레퍼런스

> 실제 구축 사례에서 뽑은 패턴 정리. 도메인에 매이지 않도록 일반화했다.
> 이론이 아니라 **깨진 지점의 기록**이 이 자료의 핵심이다.

---

## 0. 이 자료를 쓰는 법

각 원칙에 **"안 지키면 이렇게 깨진다"** 가 붙어 있다. 강의에서는 원칙을 먼저
말하지 말고 **깨진 장면을 먼저 보여준 뒤** 원칙을 끌어내는 편이 남는다.

수치를 인용할 때는 **직접 측정한 것만** 쓴다. 측정하지 않은 "N배 빨라집니다"는
한 번 쓰면 되돌릴 수 없다.

---

## 1. 한 장 요약

업무 자동화는 도메인이 달라도 네 단계로 같다.

```
수집  →  가공  →  검수  →  반영
(입력)   (AI 포함)  (사람)   (되돌리기 어려움)
```

**세 번째 단계를 빼면 자동화가 아니라 사고 발생기가 된다.**

---

## 2. 기준 아키텍처

```
  ┌─────────────┐        ┌──────────────────┐
  │  입력 소스   │───────▶│  작업(Job)        │  사람 없이 주기적으로 돈다
  │ 파일·API·화면 │        │  수집 + 가공      │
  └─────────────┘        └────────┬─────────┘
                                  ▼
                        ┌──────────────────┐
                        │  상태 저장소       │  status: 검수대기
                        │  (DB)            │  published: false
                        └────────┬─────────┘
                                 ▼
                        ┌──────────────────┐
                        │  서비스(웹 화면)   │  사람이 보고 승인한다
                        └────────┬─────────┘
                                 ▼  ← 사람이 누르는 버튼
                        ┌──────────────────┐
                        │  반영 (외부 시스템) │  되돌리기 어려운 행동
                        └──────────────────┘
```

### 왜 둘로 나누는가

| | 서비스 | 작업(Job) |
|---|---|---|
| 돌아가는 때 | 요청이 올 때 | 정해진 시각 / 수동 실행 |
| 사람 | 본다 | 없다 |
| 실패하면 | 화면에 오류 | 로그에만 남는다 |
| 배포 | 무중단 필요 | 다음 실행부터 적용 |

둘을 한 덩어리로 만들면 **수집이 실패할 때 화면도 같이 죽는다.**

---

## 3. 일곱 가지 원칙

### 원칙 1 — 되돌릴 수 없는 행동 앞에 사람을 세운다

자동화는 **직전까지만** 한다. 마지막 버튼은 사람이 누른다.

| 도메인 | 자동화 | 사람 |
|---|---|---|
| 문서 제출 | 폼 채우기, 첨부 | **최종 제출** |
| 상품 등록 | 등록(판매 안 함) | **판매 전환** |
| 콘텐츠 | 수집, 요약 | **공개** |
| 기기 제어 | 상태 조회, 예약 | **즉시 실행 명령** |

> **깨진 장면**: 금액이 잘못 들어간 상품이 자동 등록되어 그대로 팔렸다.
> 되돌리려면 주문 취소·환불·고객 응대가 따라붙는다.
> 등록은 자동, 판매 전환은 사람 — 이 한 줄이 그 사고를 막는다.

게이트는 **되돌리기 비용에 비례해** 늘린다. 돈이 걸리면 두 번 건다.

### 원칙 2 — 같은 입력은 몇 번 넣어도 한 번만 반영된다 (멱등성)

입력마다 고유 키를 만들어, 이미 처리한 것은 건너뛴다.

```python
doc_id = hashlib.sha256(source_url.encode()).hexdigest()
if ref.get().exists:
    continue
```

사용자 행동에는 **요청 ID** 를 붙여 재전송을 막는다.

> **깨진 장면**: 명령이 시간 초과로 실패한 줄 알고 사용자가 다시 눌렀다.
> 실제로는 첫 요청이 늦게 도착해 **같은 동작이 두 번** 일어났다.
> 시간 초과를 자동 재시도하면 안 되는 이유이기도 하다.

### 원칙 3 — AI 출력은 허용목록으로 검증한다

생성 결과를 그대로 저장하지 않는다. **미리 정한 값인지 확인하고, 아니면 버린다.**

```python
if topic in ALLOWED_TOPICS:
    return topic
return fallback          # 환각은 조용히 폐기
```

숫자·코드·분류처럼 **틀리면 사고가 나는 값**일수록 엄격하게 본다.
자유 서술은 느슨해도 되지만, 카테고리와 금액은 반드시 검증한다.

### 원칙 4 — AI는 선택 사항으로 만든다

AI 호출이 실패해도 파이프라인이 멈추지 않게 한다.

```python
if os.environ.get("AI_MODE", "off") != "on":
    return fallback      # AI 없이도 동작
```

> 모델 교체, 요금 소진, 장애 — 전부 일어난다.
> AI가 **없어도 60점은 나오는** 구조가 운영에서 살아남는다.

### 원칙 5 — 건별로 실패를 가둔다

```python
for item in items:
    try:
        process(item)
    except Exception as e:
        print("실패:", item_id, type(e).__name__)   # 다음 건으로 계속
```

100건 중 3건이 실패하면 **97건은 처리되어야 한다.** 전부 되돌리지 않는다.
끝에 `{"처리": 97, "실패": 3}` 을 남겨 사람이 판단하게 한다.

### 원칙 6 — "했다"를 믿지 말고 다시 읽어 확인한다

쓰기 호출이 성공했다는 것과 **값이 저장됐다는 것은 다르다.**

```
저장 → 성공 알림 확인 → 다른 화면 갔다 오기 → 다시 읽어 값 비교
```

> **깨진 장면 둘**
> - 파일 업로드 후 목록에 파일명이 보였지만 실제 전송은 되지 않았다.
>   화면만 보고 완료로 기록했다면 증빙 없이 제출될 뻔했다.
> - 에이전트가 "저장했습니다"라고 보고했지만 화면 값은 그대로였다.
>
> 그래서 상태를 **입력 / 저장 확인 / 첨부 확인 / 최종 반영 확인** 네 가지로
> 나눠 기록한다. "완료"라는 한 단어로 뭉치지 않는다.

### 원칙 7 — 비밀값은 코드와 저장소 밖에 둔다

| 두는 곳 | 쓰는 것 |
|---|---|
| 환경변수 / 시크릿 관리자 | API 키, 토큰 |
| 사람의 브라우저 세션 | 로그인, 본인인증 |
| **아무 데도** | 비밀번호를 에이전트에게 주는 것 |

로그인은 **사람이 한 번 하고 세션을 재사용**한다. 에이전트는 이미 열린
브라우저에 붙는다. 비밀번호를 넘길 일이 없어진다.

> **깨진 장면**: 유지보수가 중단된 연동 패키지에 개인 액세스 토큰을 넣어 쓰고 있었다.
> 의존 패키지의 생존 여부도 보안 점검 항목이다.

## 4. 도구 구성과 각자의 역할

```
VS Code / CLI   에이전트가 코드를 읽고 고치는 자리
     │
     ├── MCP ── 파일 / 브라우저 / 문서조회 / 외부 API
     │
GitHub          버전, 되돌리기, 자동 빌드의 기준점
     │
클라우드         서비스 + 작업(Job) + 저장소 + 시크릿
```

### MCP를 쓸 때의 기본값

| 설정 | 권장 | 이유 |
|---|---|---|
| 자동 승인(trust) | **끈다** | 파일 쓰기·셸 실행이 확인 없이 일어난다 |
| 도구 범위 | 쓸 것만 연다 | 브라우저 서버는 특히 |
| 패키지 버전 | **고정** | 매번 다른 버전을 받으면 어제 되던 게 깨진다 |
| 비밀값 | 환경변수 참조 | 설정 파일에 평문으로 남지 않게 |

## 5. 같은 패턴, 다른 도메인

| | 수집 | 가공 | 검수 | 반영 |
|---|---|---|---|---|
| **쇼핑몰 상품** | 엑셀 + 사진 | 상세설명 생성, 카테고리 매핑 | 검수대기 | 쇼핑몰 등록(판매 안 함) |
| **기관 소식** | 웹 수집 | 요약, 주제 분류 | 검수대기 | 홈페이지 공개 |
| **문서 폼 입력** | 데이터 파일 | 양식 매핑 | 화면 재조회 | 최종 제출(사람) |
| **민원 분류** | 접수 내역 | 유형 분류, 담당 배정 | 담당자 확인 | 배정 확정 |

**표의 칸만 바뀌고 구조는 같다.** 수강생에게는 자기 업무로 이 표를
한 줄 채우게 하는 것이 가장 빠른 이해 경로다.

## 6. 차시 구성 예시

### 3시간 단기

| 시간 | 내용 |
|---|---|
| 30분 | 깨진 장면 3개 시연 → 네 단계 도출 |
| 40분 | 기준 아키텍처, 서비스/작업 분리 |
| 60분 | **실습**: 자기 업무를 4단계 표로 쪼개기 → 사람 게이트 위치 정하기 |
| 30분 | 원칙 2·3·6 (멱등성, 출력 검증, 재조회) |
| 20분 | 발표와 상호 점검 |

### 1일 과정

위 3시간 + 오후에 작은 파이프라인 1개 실제 구축(수집 → 저장 → 검수 화면).

### 15주 과정

| 주차 | 내용 |
|---|---|
| 1–2 | 자동화의 네 단계, 사례 분석 |
| 3–4 | 도구 환경 구성, 버전 관리 |
| 5–7 | 수집: 파일·API·화면 |
| 8–9 | 가공: AI 호출과 **출력 검증** |
| 10–11 | 검수 화면과 상태 설계 |
| 12–13 | 반영과 배포, 되돌리기 |
| 14 | 보안: 비밀값, 권한, 의존성 |
| 15 | 팀별 발표 |

## 7. 실습 과제

### 과제 1 — 네 단계로 쪼개기 (개인, 30분)

자기 업무 하나를 골라 표를 채운다.

| 단계 | 내가 하는 일 | 자동화 가능 | 사람이 꼭 해야 하는 것 |
|---|---|---|---|

**평가 포인트**: "사람이 꼭 해야 하는 것" 칸이 비어 있으면 다시 보게 한다.
비어 있을 수 없다.

### 과제 2 — 게이트 위치 정하기 (조별, 40분)

과제 1의 흐름에서 **되돌리기 비용**이 가장 큰 지점을 찾고, 그 직전에 게이트를 둔다.
비용을 "시간 / 돈 / 신뢰" 셋으로 나눠 적게 한다.

### 과제 3 — 깨뜨려 보기 (조별, 40분)

만든 흐름에 아래를 하나씩 넣고 무슨 일이 생기는지 적는다.

1. 같은 입력을 두 번 넣는다
2. AI가 목록에 없는 값을 돌려준다
3. 100건 중 3건이 실패한다
4. 저장은 성공했다는데 값이 없다

각각에 대한 방어가 원칙 2·3·5·6이다.

## 8. 평가 루브릭

| 항목 | 미흡 | 보통 | 우수 |
|---|---|---|---|
| 단계 분리 | 뭉뚱그림 | 4단계 구분 | 각 단계 입출력 명시 |
| 사람 게이트 | 없음 | 위치만 지정 | 되돌리기 비용으로 근거 제시 |
| 멱등성 | 고려 없음 | 중복 인지 | 키 설계까지 |
| 출력 검증 | 그대로 저장 | 길이·형식 확인 | 허용목록·원자료 대조 |
| 실패 처리 | 전체 중단 | 로그만 | 건별 격리 + 결과 요약 |
| 비밀값 | 코드에 포함 | 환경변수 | 시크릿 관리 + 권한 최소화 |

## 9. 가르칠 때 흔한 함정

| 함정 | 대신 할 것 |
|---|---|
| 도구 사용법부터 가르친다 | **깨진 장면**부터 보여준다. 도구는 필요해질 때 |
| "AI가 다 해줍니다" | 사람 게이트를 **첫 시간에** 못 박는다 |
| 성공 데모만 보여준다 | **AI가 틀리는 장면과 고치는 과정**을 공개한다. 이게 가장 기억에 남는다 |
| 측정 안 한 수치 인용 | 본인이 측정한 것만. 없으면 안 쓴다 |
| 수강생 환경을 가정한다 | 설치 권한·네트워크 제약을 **미리 확인**한다. 공공기관은 외부 AI 입력이 금지된 곳이 많다 |
| 한 차시에 다 넣는다 | 50분에 들어가는 것은 **하나**다 |

## 10. 한 문장

> **자동화의 품질은 무엇을 자동으로 했는가가 아니라,
> 무엇을 자동으로 하지 않았는가로 결정된다.**
