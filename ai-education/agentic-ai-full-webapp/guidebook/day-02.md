# 2일차 — Claude Code로 풀 웹앱과 백엔드 구현

[이전: 1일차](./day-01.md) · [과정 목차](../README.md) · [다음: 3일차](./day-03.md)

## 강의 흐름
UI 화면 구현 → API 설계·구현 → DB 연결 → Oracle 백엔드 확장 → AI 요청을 통한 반복 수정과 검증.

## 실습 목표
교육용 웹앱에서 데이터 입력·목록 조회·상태 변경이 **프런트엔드 → API → DB**로 이어지는 최소 동작을 구현합니다.

## 사전 준비
- 1일차에 만든 요구사항·테스트 기준
- 독립된 개발/테스트 DB(실제 코스마 운영 DB 사용 금지)
- 서버 측에만 보관하는 환경변수와 최소 권한 DB 계정

## 따라하기

### STEP 1 — 화면 하나씩 구현
공지 목록, 신청 폼, 관리자 검토 화면을 순서대로 만들고, 더미 데이터로 먼저 확인합니다.

**완료 확인:** 화면이 뜨고 입력 값과 상태 표시가 바뀝니다.

### STEP 2 — 백엔드 API 연결
목록 조회(GET), 신청 등록(POST), 검토 상태 변경(PATCH 등)을 역할별 인증·입력 검증과 연결합니다. API 실패 시 사용자에게 오류를 보여줍니다.

**완료 확인:** 정상 요청과 잘못된 입력의 결과를 구분해 재현할 수 있습니다.

### STEP 3 — 데이터 모델 구현
예시 테이블: `notices`, `applications`, `review_history`. 레코드 ID·생성시각·검토 상태를 저장하고 변경 전후 데이터를 확인합니다.

**완료 확인:** 저장 → 조회 → 수정 → 재조회 결과가 일치합니다.

### STEP 4 — Oracle 백엔드 확장 실습(신규 교육 내용)
Oracle DB는 **기존 코스마 홈페이지 구현 사실이 아니라 별도 확장 실습**입니다. 테스트용 Oracle 환경을 준비하고 DB 접속 방식, 스키마, 드라이버, SQL 차이를 비교합니다. 실제 설치 명령·DSN·무료 사용 조건은 교육 환경 확정 후 문서에 기입합니다.

**완료 확인:** 독립된 Oracle 실습 DB에서 더미 데이터를 저장·조회합니다. 환경이 준비되지 않았다면 설계 비교까지만 진행합니다.

### STEP 5 — Claude Code로 수정 요청
```text
현재 교육용 웹앱에서 신청 목록을 조회한 뒤
관리자는 승인/반려 상태를 변경할 수 있어야 합니다.
먼저 변경할 파일과 API, 데이터 스키마, 테스트를 제시하세요.
기존 저장/조회 기능을 깨지 않게 최소 범위로 수정하고
실행한 테스트 결과와 아직 검증하지 못한 부분을 구분해 보고하세요.
```

**완료 확인:** 수정 파일 목록, 테스트 결과, 남은 이슈가 기록됩니다.

## 흔한 오류와 복구
- **CORS/OPTIONS 오류:** 브라우저 요청 출처와 서버의 허용 출처를 확인합니다.
- **DB 연결 실패:** DB 접근제어, 호스트·포트·서비스명, 계정 권한을 점검합니다(비밀번호 노출 금지).
- **AI 수정 후 회귀 오류:** 변경 전 동작을 테스트하고 Git 이력과 비교합니다.

## 산출물
동작하는 교육용 웹앱, API 목록, DB 스키마, 변경·검증 기록.

> **검증 상태:** 실습 순서 초안입니다. Oracle 연동 코드는 실제 교육용 DB·드라이버 환경에서 검증한 뒤 추가합니다.
