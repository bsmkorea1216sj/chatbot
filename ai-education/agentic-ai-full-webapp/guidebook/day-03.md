# 3일차 — 클라우드 배포, 운영 점검과 오류 해결

[이전: 2일차](./day-02.md) · [과정 목차](../README.md)

## 강의 흐름
배포 전 검증 → 클라우드 서비스·환경변수 → 배포 → 로그 분석·재배포 → DNS·인증·보안·비용.

## 실습 목표
교육용 웹앱을 운영 환경과 분리된 **실습 서비스**로 배포하고, 실패 원인을 로그로 확인해 수정·재검증하는 경험을 얻습니다.

## 사전 준비
- 2일차 교육용 웹앱과 테스트 기록
- 실습용 클라우드 프로젝트 및 권한·예산 확인
- 환경변수·비밀관리·로그 접근 권한
- 비용 발생 가능성이 있는 리소스는 강사 안내에 따라 별도 승인

## 따라하기

### STEP 1 — 배포 전 검사
필수 파일, 의존성, 환경변수 이름, 서버 시작 방식, 헬스체크, 자동 테스트 여부를 확인합니다.

**완료 확인:** 배포 체크리스트와 테스트 결과를 저장합니다.

### STEP 2 — 아키텍처 선택
예시로 GCP Cloud Run을 소개하고, 브라우저 → HTTPS 엔드포인트 → 컨테이너 API → 외부/관리형 DB 연결 구조를 그립니다. Oracle DB 연결은 네트워크·비밀관리 설계를 따로 확인합니다.

**완료 확인:** 환경별 서비스·DB·비밀 저장 위치가 문서화됩니다.

### STEP 3 — 실습 배포
교육용 클라우드 프로젝트에서 컨테이너 배포를 진행하고 배포된 URL의 응답 및 저장/조회 기능을 확인합니다. 구체적인 실행 명령은 강사 실습환경 검증 뒤 추가합니다.

**완료 확인:** URL 접근과 기본 API 헬스체크가 성공합니다.

### STEP 4 — 오류 진단 실습
다음 문제 유형을 순서대로 재현하거나 기록 사례로 분석합니다.
1. 실행 명령/포트 불일치로 서버 시작 실패
2. 비밀값·서비스 계정 권한 부족
3. DB 네트워크 연결·타임아웃
4. CORS/인증/도메인 경로 오류
5. 기능 수정 뒤 회귀 테스트 실패

**완료 확인:** 관찰된 증상 → 로그 → 원인 가설 → 수정 → 재검증을 1개 이상 기록합니다.

### STEP 5 — Claude Code 수정 프롬프트
```text
다음은 교육용 웹앱 배포 실패 로그입니다(비밀값은 제거했습니다).
로그로 확인되는 사실과 추정 원인을 구분해 주세요.
가장 작은 안전한 수정안을 제시하고 변경 파일, 재현 방법,
로컬 테스트, 재배포 전 점검, 실패 시 복구 방법을 정리해 주세요.
운영 중인 코스마 홈페이지 설정은 변경하지 마세요.
```

### STEP 6 — 운영 마무리
인증/권한, 비밀관리, 최소 로그, DB 백업·복구, 도메인/DNS, 월 비용 알림, 복구할 이전 배포 리비전을 점검합니다.

**완료 확인:** 배포 검증 기록과 운영 체크리스트가 완성됩니다.

## 산출물
교육용 배포 구성도, 테스트 URL(개인 실습환경에서 생성), 장애 원인·해결 기록, 운영·비용 체크리스트.

> **검증 상태:** 배포·오류 실습의 절차 초안입니다. 실제 계정의 배포 완료, URL 생성 또는 비용 검증을 의미하지 않습니다.
