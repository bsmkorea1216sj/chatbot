# 1일차 — 프로젝트 요구사항부터 AI 개발환경까지

[과정 목차](../README.md) · [다음: 2일차](./day-02.md)

## 강의 흐름
업무 문제 정의 → 사용자 역할 → MVP 설계 → 화면·API·DB 구조 → GitHub/Claude Code 작업 방식.

## 실습 목표
코스마 홈페이지 구축 경험을 예시로 **운영 서비스와 분리된 교육용 협회 웹앱**의 요구사항 및 구현 계획을 작성합니다.

## 사전 준비
- GitHub 계정과 개인 실습용 저장소/브랜치
- Claude Code 사용 가능한 로컬 개발환경
- 테스트용 가상 공지·회원·관리자 데이터
- **운영 서버, 실제 사용자 데이터, 운영용 API 키는 사용하지 않음**

## 따라하기

### STEP 1 — 요구사항 쪼개기
방문자(공지 열람), 회원(교육 신청), 관리자(승인·관리)로 역할을 나누고 각 역할의 화면과 권한을 작성합니다.

**완료 확인:** 사용자 역할 3개와 화면별 할 일이 표로 정리됩니다.

### STEP 2 — MVP 범위 정하기
첫 구현은 공지 목록·상세, 신청 폼, 관리자 승인 상태 확인으로 한정합니다. 알림·검색·분석은 다음 단계로 분리합니다.

**완료 확인:** 필수/선택 기능이 구분됩니다.

### STEP 3 — 아키텍처 초안
브라우저 → 백엔드 API → 데이터베이스 → 응답의 흐름을 그립니다. 인증 및 AI 기능을 어느 계층에 추가할지 표시합니다.

**완료 확인:** 요청과 응답 흐름을 설명할 수 있습니다.

### STEP 4 — Claude Code에 계획만 요청
```text
교육용 협회 웹앱을 개발할 예정입니다.
먼저 코드를 변경하지 말고 방문자·회원·관리자 권한,
최소 기능(MVP), 화면 목록, REST API 목록, DB 테이블,
구현 순서와 단계별 테스트 기준을 표로 정리해 주세요.
운영 홈페이지나 실제 개인정보·비밀키를 사용하지 마세요.
```

**완료 확인:** 코드 변경 없이 계획과 검증 기준이 도출됩니다.

### STEP 5 — GitHub 작업 분리
실습용 브랜치/저장소를 확인한 뒤, 계획 문서를 커밋합니다. 기존 서비스 코드의 현재 브랜치·변경 파일과 뒤섞이지 않도록 경로를 점검합니다.

**완료 확인:** 변경 목록에 실습용 문서만 표시됩니다.

## 흔한 오류와 복구
- **AI가 곧바로 대량 구현:** 먼저 계획만 요청하고 단위 기능별 승인 후 구현합니다.
- **과정/브랜치 혼동:** 작업 디렉터리와 브랜치를 확인하고 미리보기 변경 목록을 검토합니다.
- **비밀정보 노출 위험:** 실제 키를 채팅·코드·커밋에 붙여넣지 않습니다.

## 산출물
요구사항 요약, MVP 목록, 아키텍처 다이어그램 초안, 기능별 테스트 기준.

> **검증 상태:** 교육용 절차 초안입니다. 개별 운영체제와 Claude Code 버전에 따른 설치 화면·실제 실행 결과는 추후 검증하여 추가합니다.
