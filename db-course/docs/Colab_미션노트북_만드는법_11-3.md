## 2. 노트북 셀 순서 (고정 형식)

```
[MD]   제목 · 진행 방법 · 노트북 ↔ 교안 쪽수 대응표
[CODE] ✅ 미션 확인 도우미 (#@title … form 으로 코드 숨김, HELPER_V 버전)
── 섹션 반복 ───────────────────────────────────────────
[MD]   ## n. 따라하기 · 주제 (교안 ○쪽)
[CODE] 🔎 예측 퀴즈            id = quiz_qN
[CODE] 따라하기 코드 (표 만들기·조회, HTML 표 출력)
[MD]   > 결과 읽는 법 (실제 출력값으로 설명)
[MD]   ## 🎯 미션 k · 제목 (교안 ○쪽)   id = mission_mk   ← 교안 버튼 링크 대상
[CODE] 🎯 미션 k 셀 (input → check → retry)
────────────────────────────────────────────────────────
[MD]   ## 📝 과제 (교안 ○쪽)            id = mission_hw
[CODE] 과제 셀 (input → check → retry)
```

- **미션 번호 = 교안에 나오는 순서.** 교안을 넘기면 미션이 1→2→3→4→5 순서로 나와야 한다. 노트북 섹션 순서도 이에 맞춘다.
- 교안 버튼 링크: `https://colab.research.google.com/drive/<노트북ID>#scrollTo=mission_mk`
  → **미션 마크다운 셀의 `metadata.id`를 `mission_<k>`로 고정**한다.
- 노트북을 다시 올릴 때 **기존 셀 ID를 보존**한다(강의자가 이미 공유한 `#scrollTo=` 링크가 깨지지 않게).

- `#@title … { display-mode: "form" }` 으로 **코드를 숨기고 실행 버튼만 보이게** 한다.
- check 함수는 **정답 문자열을 출력하지 않는다.** "다시 볼 항목", "힌트: 교안 ○쪽 표"처럼 안내만 한다.
- 데이터를 바꾸는 미션(INSERT/DELETE)은 **SAVEPOINT → 확인 → ROLLBACK**으로 실습 데이터를 원래대로 되돌린다
  (틀린 입력이 다음 따라하기 결과를 망치지 않게).

## 4. 미션 셀 형식 (모든 미션·과제·퀴즈 공통)

```python
# 🎯 미션 3 · 합계와 부가세를 구하는 식을 입력하세요 (틀리면 바로 다시 입력)
if globals().get('HELPER_V') != 2:   # GUARD: 도우미 미실행·옛 버전이면 노트북에서 자동으로 불러옴
    try:
        from google.colab import _message
        exec(next(''.join(c['source']) for c in _message.blocking_request('get_ipynb')['ipynb']['cells']
                  if ''.join(c['source']).startswith('#@title ✅')))
    except Exception:
        print('⚠️ 맨 위 ✅ 미션 확인 도우미 셀을 먼저 실행(▶)하세요.'); raise SystemExit
# 사용할 수 있는 열: m.unit_price(단가), i.qty(수량) · 함수: SUM( )
def mission3():
    total_expr = input('① 합계(total)를 구하는 식: ').strip()
    vat_expr   = input('② 부가세(vat)를 구하는 식: ').strip()
    sql = f"SELECT {total_expr} AS total, {vat_expr} AS vat FROM order_items i JOIN menu m ON m.menu_id = i.menu_id WHERE i.order_id = 'B0001'"
    print(sql)
    return check_m3(sql)
retry(mission3, page=9)
```

규칙
1. **첫 줄 주석** = 미션 번호·할 일·"틀리면 바로 다시 입력" (GUARD는 첫 줄 바로 다음에 자동 삽입: `missions._g()`).
2. **빈칸 채우기(____) 금지** → 학생이 코드를 고치다 열 이름을 잘못 넣는 문제가 있었음. 반드시 `input()`으로 값만 받는다.
3. 입력칸 문구에 **형식 예시**를 넣는다: `"④ payments.order_id 가 가리킬 '표(열)' 예: 표이름(열이름)"`, "(숫자)", "(따옴표 없이)".
4. 입력값으로 SQL을 조립해 **print(sql)** 로 보여 준 뒤 check → 학생이 자기 답이 어떤 SQL이 되는지 본다.

## 부록 · 5차 정규화 Q&A (11-2 수업 질문)

**Q. 5차 정규화는 나눠서 문제가 되면 나누지 않는 것인가?**
A. 절반만 맞다. 기준은 **"나눴다가 다시 JOIN했을 때 원본이 항상 그대로 복원되는가(조인 종속)"** 이다.

| 경우 | 다시 JOIN하면 | 할 일 |
|---|---|---|
| ① 업무 규칙상 항상 복원됨 (조인 종속 성립) | 가짜 행이 절대 안 생김 | **세 표로 나눈다** → 중복 제거 (5차 정규화를 '하는' 경우) |
| ② 복원 안 됨 | 가짜 행 생김 (11-2 예: (10, PA, DBA)) | **나누지 않는다** → 이미 5NF |

- ① 예시 규칙: "사원이 프로젝트에 참여하고, 그 사원이 기술을 보유하며, 그 기술이 그 프로젝트에서 쓰이면 → 그 사원은 그 프로젝트에서 반드시 그 기술을 쓴다." (교과서 예: 영업사원–회사–제품)
- 4차 정규화와 차이: 4차는 한 결정자가 두 목록을 독립 결정 → **두 표**로 분리(항상 복원). 5차는 두 표로는 안 되고 **세 표 이상**에서만 복원되는 관계를 다룬다.
- 11-2 교안 28~30쪽은 ②만 보여 주므로, ① 예시 1장을 추가하면 오해("5NF = 나누지 않는 것")를 막을 수 있다(미반영).
